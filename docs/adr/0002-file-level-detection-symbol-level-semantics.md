# Incremental staleness: file-level detection, symbol-level semantics

Change detection re-parses at file granularity (content-hash trigger) — millisecond-scale per the design-time web-tree-sitter benchmark, and the same route every surveyed tree-sitter tool takes. Symbol-level incremental indexing was explicitly rejected: it is a known cross-file-edge bug magnet in fork projects, with no payoff at CLI scale. Semantic precision still comes from symbols: re-parsed files are diffed at symbol level into signature-changed / body-changed / gone, mapped onto Broken and Drift anchors. Engine: web-tree-sitter (WASM) with official grammar npm packages; TS/JS and Java queries ship in v1. Call-edge propagation is deferred to v2 and will be name-heuristic, with its blind spots documented.
