# Anchor grammar: a markdown link title carrying a dual-hash fingerprint

An Anchor is a standard markdown link — `[text](target "c2d:<file>#<name>:<sig>.<body>")` — where the entire machine payload rides in the double-quoted link title and the URL is left for human Readers (the verifier never parses it). `<sig>` and `<body>` are the 16-hex-truncated sha1 hashes from the extractor. Resolution is by repo-relative file path + symbol name only; the row in a symbol id is cache-local, so line shifts can never break an anchor. Signals: symbol missing or signature hash mismatch → Broken (exit 2); body-only mismatch → Drift (exit 1); otherwise fresh (exit 0). A page's state is the worst of its anchors; page-level "fresh" is the glossary's Accurate. A manifest page with no file on disk reports broken with a note rather than passing silently.

Fingerprint hashing cuts comment node ranges at AST granularity (a regex would misfire on `//` inside string literals) and collapses whitespace runs to single spaces, so comment-only and reflow-only edits produce no false signals while single-space differences — inside string literals especially — stay significant: false stale is recoverable, silently-fresh stale is not. Known limits, accepted for v1: whitespace runs inside string/template literals are normalized; adding or removing a space between tokens is a (conservative) signature/body change; two same-named top-level symbols in one file resolve to the first; a visibility change (adding/removing `export`) does not alter fingerprints; link titles must use double quotes.

`status` always brings the cache to current state before verifying (file-hash-triggered re-parse per ADR-0002), so anchors are checked against the code as it stands. The cache carries a `version` that is bumped whenever the fingerprint algorithm changes; a cache with a foreign version is discarded and rebuilt rather than reused, so old-algorithm fingerprints can never poison verification.
